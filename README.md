# Verba et Acta

우리가 사용하는 것이 무엇을 하는지, 우리는 알아야한다.

*We should know what the things we use actually do. Reports are written in Korean.*

## 원칙

1. **분석 범위** — 우리가 쓰는 서비스와 소프트웨어를 다룹니다. 직접 설치한 앱과 프로그램의 분석, 공개 소스 검토, 공개 문서 비교를 하며, 허락받지 않은 서버 접근, 타인 계정 접근, 인증 우회는 일체 하지 않습니다.
2. **서술 기준** — 확인된 사실과 확인하지 못한 사항을 구분해 적습니다. 본 작성자는 법률 전문가가 아니기에, 위법 여부는 판단하지 않습니다.
3. **취약점** — 악용될 수 있는 보안 취약점은 공개하지 않고 해당 회사, 오픈소스 메인테이너, 또는 KISA에 먼저 알립니다. 내용은 패치가 배포된 뒤에 공개합니다. 제보일로부터 30일 동안 응답이 없으면 공개하며, 응답이 있으면 공개 시점을 협의합니다.
4. **반론과 정정** — 회사의 설명이나 반론은 받은 대로 싣습니다. 오류는 지우지 않고 고친 뒤 수정 내역을 투명하게 남깁니다.
5. **요청** — 분석 요청은 받지만, 개인을 대상으로 한 분석, 유출 자료 분석, 대가를 받는 분석은 하지 않습니다. 요청을 받아 쓴 글은 그 사실을 글에 밝힙니다.
6. **금전과 연락** — 돈을 요구하지 않으며, 돈을 받고 글을 쓰거나 지우지 않습니다. 회사에 먼저 연락하는 경우는 질의와 취약점 제보뿐이고, 아래 메일 또는 회사가 정해 둔 제보 창구로만 합니다. 글을 올리지 않거나 내리는 대가로 돈을 요구하는 연락을 받았다면 Verba et Acta를 사칭한 것입니다.
7. **인용** — 글은 누구나 인용할 수 있습니다. 인용할 때는 작성자(Verba et Acta)와 글의 주소를 함께 적어 주시기 바랍니다.

## 오픈소스 보안 제보

한국에서 만들어졌거나 한국에서 널리 쓰이는 오픈소스 프로젝트의 소스 코드를 검토해, 발견한 취약점을 메인테이너에게 비공개로 제보합니다. 보상은 요구하지 않습니다. 패치가 끝난 건만 이곳에 기록합니다.

검토 요청도 받습니다. 메인테이너가 아니어도 신청할 수 있고, 현재는 GitHub 별 10개 이상이거나 실제 사용처가 확인되는 프로젝트만 받습니다. 신청은 아래 메일로 보내 주시기 바랍니다. 결과는 신청자가 아니라 메인테이너에게 먼저 알립니다.
